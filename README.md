# CET-4 真题词汇提取工具

从历年四级真题语料中自动抽取重点词，每个单词都配上**真题原句 + 题目情境 + 年份题型出处**，
按等级、年份、题型归类，导出可交互网页、Markdown 词表、Anki 卡片包。

> ⚠️ **先说明一句**：语料里 2025-06 起的 3 个场次是可在公开来源核实的真题片段，
> 2021-06 ~ 2024-06 这 8 个场次是按真题题材与难度**人工撰写的仿真语料**（占词次 86%）。
> 页面与导出的每一条例句都标了来源，出现次数也拆成「真题 n 次 · 仿真 m 次」两个数。
> 详见 [「先说清楚：哪些是真题，哪些是仿真语料」](#先说清楚哪些是真题哪些是仿真语料)。

面向基础薄弱（四级 370 分区间）的使用者设计：优先 A 级**基础高频词**与 B 级**核心必背词**，
释义只给常考义，不堆生僻义；学习页内置**每天 30 词**的今日计划，不用自己排进度。

这 1634 个词覆盖真题正文 **96.5% 的实词**（去掉 the / a / of 这类功能词后，
命中 5877 / 6088 个词次）；算上功能词是 64.6%（6656 / 10309）。
换句话说：把这些词背完，正文里每 20 个需要认识的词，还有 1 个没见过。

**在线版**：https://klb299.github.io/cet4-word-miner/
（手机浏览器打开后可用「添加到主屏幕」，像 App 一样用）

## 一、三分钟上手

```bash
cd cet4-word-miner
python run.py                 # 构建全部输出，并自动打开学习网页
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--levels AB` | 只保留基础高频 + 核心必背（推荐 370 分档先用这个） |
| `--examples 5` | 每个词最多 5 条真题例句 |
| `--min-count 2` | 只要真题中出现 2 次以上的词 |
| `--only-years 2025年6月,2024年6月` | 只保留指定场次，逗号分隔 |
| `--check` | **只做数据体检**，不生成文件（改完语料先跑这个） |
| `--no-open` | 不自动打开浏览器 |

`--check` 会检查：词库格式错位、词条重复、义项里混入英文残留、语料中正文过短或缺题干的块、
哪些块没配译文、哪些词义项过多导致卡面过长、**哪些词缺音标或音标看着不像音标**。
**改动 `data/` 之后建议先跑一遍再看结果。**

输出目录 `output/`：

| 文件 | 用途 |
|---|---|
| `index.html` | **主学习页**：词卡 / 拼写 / 听写 / 选词填空做题、三档自评与复习队列、音标与朗读、导出 |
| `真题词汇表_按年份题型.md` | 按年份 → 题型 → 词条整理的三线表 |
| `真题词汇表_完整.csv` | 全字段表（含音标、上文、下文、原题），Excel 可开 |
| `Anki导入包.csv` | 三列开箱即用：正面=单词+音标+真题句，背面=词性+释义+出处 |
| `未收录高频词.txt` | 语料里高频但词库没收的词，纯文本清单（取前 300，快速浏览用） |
| `未收录词工作台.html` | **全部**未收录词的带例句版，边看语境边补词库 |
| `manifest.webmanifest` / `sw.js` / `icon.svg` | PWA 三件套：添加到主屏幕、断网可用 |

> 工作台列的是**全部**未收录词（约 400 个），不是清单里的前 300。
> 前 300 按"正文出现次数"排下来全是正文里出现过的词，
> 那样页面上「只在题干/选项出现过」这档筛选永远筛不出东西，等于给了个死开关。

### 先说清楚：哪些是真题，哪些是仿真语料

这个工具叫「真题词汇」，但**不是所有语料都来自考场**，卡面上把两者分得很清楚：

| 来源 | 场次 | 题型块 | 占词次 |
|---|---|---|---|
| 真题片段（可在公开来源逐句核实） | 2025-06 及以后 | 23 | 14% |
| 仿真语料（按真题题材与难度人工撰写） | 2021-06 ~ 2024-06 | 60 | 86% |

- 每条例句前面都有来源徽章：写「真题」的才是考场原句，写「仿真」的是补样本用的撰写文本。
- 出现次数拆成两个数：`真题 18 次 · 仿真 177 次`。只有仿真里出现过的词，卡面直接写「仿真出现 177 次」，
  不会用「真题」开头。
- **仿真句的出现次数不等于考场频次**，它只说明"这类题材里这个词常见"。
  词序（等级 → 频次）里频次这一维仍然以仿真语料为主，这一点请不要当成真题高频榜。
- 精读视图的篇章选单里，仿真篇目标着【仿真】；导出的 MD / CSV / Anki 卡片同样带来源标注。

为什么不做成全是真题：CET 官方不公布真题原文（<https://cet.neea.edu.cn> 只发考试时间与成绩查询），
2025 年以前的卷子公开渠道只有机构解析与考生回忆版，逐字核实不了。
详见 `data/2025-2026来源说明.md`。

## 二、学习页怎么用

顶部有三个视图：`背单词` / `精读` / `做题`。背单词里再用「练习方式」下拉切换 看卡 / 拼写默写 / 听力听写。

### 每天背多少：今日 30

1600 多个词一次摊在页面上，最难的其实不是背，是"今天该背哪几个"。所以页面上有一个 **今日 30** 开关：

- 点开后只显示 30 个词：**先排到期复习的词**（昨天打了「模糊」、今天该回看的），
  再按等级与频次顺序用**没学过的词**补位。
- 补位时跳过 `be / has / have / not` 这类纯功能词——按频次排序榜首先是它们，占掉名额没有意义。
- 顶部进度行显示 `今日 12/30 · 连续 3 天 · 明天 8 · 已掌握 45/1634`。
  **明天 8** 是提前量：今天就看到明天要复习多少个，不会等到明天再慌。
- 同一个词一天只计一次，改自评不会把进度刷上去；跨天自动归零，昨天打过卡才算连续。
- 第一次打开时会有一句引导，有进度之后自动消失。

按 30 个/天算，1634 个词约 55 天走完一轮。

### 难词：总记不住的那批，单独拎出来

- 判定条件：**答对次数不到 2 次，且当前还是「不会 / 模糊」**。
  SRS 队列里它们会天天出现，但和"第一次见"的词混在一起，看不出这 30 个里有一半是钉子户。
- 按钮上带个数（`难词 (12)`），点一下只留这批。
- 计数只算卡片里真实存在的词——`srs` 里可能留着被 `--levels` / `--min-count`
  筛掉的词，不过这一层就会出现「难词 (3)」点进去只有 2 张。

### 断了几天回来

打开时如果距上次学习 **≥3 天**且有词到期，列表顶部会给一条提醒：

> 上次学习是 4 天前。今天有 3 个词到期，先点上面的「今日复习」清掉，再学新的。

比"接着学新词"更要紧的是先清欠账——否则明天会翻倍。上次打开的日期存在
`cet4_last_open_v1`，跨设备不同步（本地存储）。

### 同族词：认识一个，认出一串

四级阅读里的"生词"常常不是完全陌生，而是换个词性就认不出——认识 `produce` 卡在
`production` 上，认识 `care` 反应不过来 `careless`。卡面在释义下面给出 **同族**：

- 做法只靠**后缀剥离**：剥掉 `-tion / -ment / -ness / -ity / -ive / -ful / -less / -ly / -al`
  之后，必须能在词库里查到原形，才算一族。不猜词根，宁可少连——
  `career` 绝不会被连到 `care` 上。
- 210 多个词条有同族提示（如 care ↔ careful、produce ↔ production、create ↔ creative ↔ creativity）。
- 紫色按钮可以点，点了跳到那个词；灰色的（如 `nation`）说明词库有这个词、
  但真题里没出现，所以没有卡片——不骗你能点。
- 为了让族连得起来，补了一批"有派生词却没有原形"的词：
  `actual`（← actually）、`equal`（← equality）、`absent`（← absence）、`frank`（← frankly）…

### 易混词：认识但看错，才是最常见的失分

阅读里真正的坑往往不是"这个词不认识"，而是"我认识，但看成了另一个词"。
卡面在释义下面给一行 **易混**，点一下就跳到那个词：

- 判定只靠拼写：**差一个字母**（adapt / adopt、affect / effect、advise / advice），
  或者**相邻两字母换位**（form / from）。
- 4 个字母以下的词不做提示——`for / far`、`of / off` 这种"差一个字母"在短词里几乎必然成立，
  全是噪音。词库里 319 个词条有易混提示。
- 排序看三件事：同词性优先 → 拼写距离近优先 → 真题里常考优先。

### 精读难度：这篇现在读起来累不累

精读的选单里，每篇后面都标着 `（生词 42）`——按你**当前掌握情况**算出来的。
点开一篇，标题下面会有一行评估：

```
全文 188 词 · 还没掌握 99 个重点词（占全文词次 64.9%）· 太难
```

- 分子是"你还没掌握的词在这篇里出现了多少次"，分母是全文词次。
  不能拿生词**个数**除词次：188 词里有 60 个生词，密度不是 32%，
  而是这些生词占了多少个词位。
- 分档：≥15% 太难、≥8% 偏难、≥3% 合适、其余很轻松。
  刚打开时每篇都会显示「太难」，那是在提醒你先去背今日 30。
- **推荐下一篇**按生词从少到多排成一条升级路线，点一次走一篇；
  会跳过 80 词以下的块（选词填空八九个词，密度会被一两个词带偏）。
- 这个数字随你的进度实时变化：背会 300 个词之后，同一篇的密度会从 65% 掉到 26%。

### 精读：整篇真题原文

83 个题型块的完整原文都在，按篇章选择，重点词高亮、逐句带译文、逐句可朗读：

- **只高亮 B/C 级（核心必背 + 进阶拓展）**。A 级基础词（they / has / for / it）不高亮——
  不然补完基础词之后整篇几乎全黄，高亮就失去了"提醒你这里有个值得看的词"的作用。
  唯一例外是**固定搭配**（rather than / no longer / for example…）：它们虽然全是 A 级，
  但整篇只有 51 处，而且恰恰是阅读里最容易看漏的考点，所以照样标出来。
- 每句右边一个小 🔊 整句朗读，练听力语感比只读单词有用。
- 译文逐句跟在后面，右上角一键开/关。
- 底部「**本文重点词 n 个**」列出这篇命中的全部词，按等级着色（绿=基础 / 蓝=核心 / 紫=进阶），
  点词朗读。先读一遍原文再背这些词，比孤立背词表记得牢。
- 题干和选项也列在文末。
- 打印时精读视图印整篇文章（单栏、逐句带译文），其余视图印词卡双栏表。

- **👁 显示译文**：右上角眼睛开关，一键切换全部真题原句和原题的中文翻译（默认隐藏，先看英文猜意思）。
  每句旁边还有单独的小眼睛，可以只露出这一句的翻译。
- **自测模式**：默认开启，释义被打码，点击才显示，逼自己先回忆。
- **三档自评 + 复习队列**：每张卡片底部三个按钮，替代原来那个二元的"标记为已掌握"——

  | 按钮 | 含义 | 下次出现 |
  |---|---|---|
  | 不会 | 完全想不起来 | **今天**就会再出现 |
  | 模糊 | 想起来了但慢 | 明天 |
  | 会 | 顺利回忆 | 间隔 1 / 2 / 4 / 7 / 15 / 30 / 60 天，连对越多次隔得越久 |

  顶部「**今日复习 (n)**」一键只看过期该复习的词，没学过的也算在内。
  数据存浏览器本地；旧版本的"已掌握"记录会在第一次打开时自动平移成"会"，进度不丢。
  本地数据万一被写坏（浏览器扩展、旧版本残留、手改），只会当作没学过，**不会白屏**。
- **拼写默写**：单词和原题都藏起来，只给释义 + 音标 + 读音，你拼出来回车判定。
  拼错自动记成"不会"，两秒半后显示正确写法；拼对自动记成"会"并跳到下一个词。
  例句里的目标词也挖空了，不然就剧透。
- **听力听写**：单词、句子全藏，只剩一个大喇叭。先听后写，再点「显示答案」对照。
  这是对付四级听力最直接的练法，1559 张卡片带可朗读的真题例句。
- **做题（选词填空）**：切到"做题"视图，从当前筛选出的词里抽 20 道题。
  每题给一句真题原句挖空 + 4 个**同等级同词性**的候选词，即时判分；
  答错的那道自动记成"不会"，今天就会再出现。答完有本轮正确率。
  出题只挑**词形与原形一致且带译文**的句子，保证空格和选项对得上。
  **译文默认收起**：整句的中文翻译里往往就写着空格处那个词的意思，开局摊开等于把答案递到手上；
  答完才自动展开当讲解。实在想不出来可以点「看译文」自己展开，不扣分。
- **只看高频**：只出现 1 次的词约占四分之一（约 420/1634），考前时间紧就用这个把长尾先放一放。
- **筛选**：等级（A 基础高频 / B 核心必背 / C 进阶拓展）、年份、题型可任意组合。
- **每张卡片包含**：单词、**音标**、词性、义项、常考搭配、**真题原句（目标词高亮）**、上文/下文、
  题目情境、该题原题、年份·套次·题型出处、"此处作名词/动词"的语境提示。
  例句可能来自**正文句、题干或选项**（题干和选项那条会单独标出来）。
- **打印 / PDF**：按 `Ctrl+P` 或点顶部按钮。
  打印的是**当前筛选出的全部单词**，不是屏幕上那几十张——列表是分页渲染的，
  直接印只能印出已加载的部分（1272 个词里印出前 40 个这种事以前真发生过）。
  想少印点就先用等级 / 只看高频筛一遍。
  打印时还会**换成一套紧凑版式**，不是把屏幕上的卡片直接印出来——

  | | 屏幕上 | 纸上 |
  |---|---|---|
  | 例句 | 每词最多 3 条 | 只留 1 条 |
  | 出处标签、上文/下文、原题 | 显示 | 隐藏 |
  | 三档按钮、喇叭、收藏星 | 显示 | 隐藏 |
  | 译文、释义 | 按开关 / 打码 | 强制展开、强制去模糊 |
  | 版式 | 单栏 | A4 双栏，卡片不跨页断开 |

  为什么必须分两套：屏幕版每张卡带 3 条例句加出处、上下文、原题，
  实测打印时卡片高 1105px，比 A4 可用高度（约 1032px）还高，
  于是「卡片不跨页」只能一页印一张，240 张打出 230 页。
  换成紧凑版式后同样的 240 张只占 28 页（全量 1634 词约 173 页）。
- **进度**：标记"已掌握"存在浏览器本地，下次打开还在。
- **导出**：按当前筛选条件导出 Anki CSV，**分列**给出
  `word / phonetic / pos / senses / sentence / trans / source / level`，
  方便在 Anki 里自己搭模板（`output/Anki导入包.csv` 则是三列开箱即用版，两者用途不同）。

### 读音与音标

- **音标**显示在词头右侧，美音，如 `abandon /əˈbæn.dən/`。
- **朗读**有两条路可走，默认走第一条：

  | 顺序 | 方式 | 说明 |
  |---|---|---|
  | 1 | 浏览器自带的语音合成 | 不联网、不依赖外部服务，**断网打开本地文件照样能读** |
  | 2 | 在线发音 | 只在系统一个英文语音都没有时才启用 |

  Windows 上如果没声音，装一个英文语音包即可：设置 → 时间和语言 → 语音 → 添加语音。
- **怎么读**：点单词本身，或点它右边的 🔊；每条真题例句末尾也有一个小 🔊，可以整句读。
  读例句对练**听力**和**翻译**语感比只读单词有用得多。
- **语速三档**：顶部「语速」按钮循环 常速(1.0) → 慢速(0.7) → 很慢(0.5)。
  跟读和听写用 0.5 倍速比调系统音量有效。档位记在本地，下次打开还是上次那档。
- 手机上朗读需要**先点一下**（浏览器规定语音必须在用户操作里触发），页面里所有朗读都挂在点击上，
  所以点一下就能读。

### 搜索怎么用

- **双向搜索**：搜索框右侧的「英→中 / 中→英」切换方向。
  - **英→中**（默认）：输入英文，匹配单词、释义、真题原句。
  - **中→英**：输入中文，在**释义、真题句译文、原题译文、题目情境、搭配提示**里反查，
    命中的中文会高亮。比如搜「尽管」，正向只找到 3 个词（释义里写了"尽管"的），
    反向能找到 42 个（译文中出现"尽管"的也算）。
  - 切换方向时**输入框里的字和年份/题型/等级等筛选全部保留**，不用重新输一遍。
- **搜索历史**：输完停顿 1 秒、按回车或点开别处，关键词自动记下来，存在浏览器本地，
  关掉再打开还在。点某一条即可回填（连当时用的方向一起恢复），
  每条右边的 × 单条删除，末尾「清空」一次清完。最多留 10 条。
- **收藏**：点单词卡片右上角的 ★ 收藏，顶部「★ 收藏 (n)」可切成只看收藏的词，
  用来反复回看常错词。收藏同样存本地。
- **搜不到时**：空结果会直接说清卡在哪（是不是等级被隐藏了、是不是开着"只看未掌握"、
  是不是限定错年份），并给出「清空搜索词 / 试试反向反查 / 显示全部等级 / 重置筛选」
  这类能直接点的按钮，不用自己猜是哪一层筛掉了。
- **快捷键**：`/` 或 `Ctrl/⌘+K` 聚焦搜索框，`Esc` 清空搜索词，
  `Alt+R` 切换正反向，`Alt+F` 只看收藏，`Alt+D` 今日复习，
  `Alt+S` 朗读第一个词，`Alt+1` 换语速。

### 未收录词工作台

`output/未收录词工作台.html` 是个独立的小页面，列真题里出现过、但词库没收的词，
每条带 1-2 条正文例句和一条可直接复制的词库行模板。
边看语境把义项填好，粘进 `data/lexicon/` 再重跑就行。
之所以单独出页面而不塞进主页面：它是给"加词库的人"用的维护工具，
和"每天刷词的人"的使用场景完全不同，混在一起只会互相干扰。

几条设计：

- **出现次数分两个数**：`正文` 指这个词在真题原文里出现过几次，`总计`还包含题干和选项。
  排序按正文次数来——只在题干里露过脸的词多半是套话，补进词库的价值低。
- **可按来源筛**：「只在正文出现过」/「只在题干、选项出现过」。
- **噪音已过滤**：`data/stopwords.txt` 里是功能词（the / and / that）、
  题干套话（mainly / passage / exams / directions）、专有名词（人名地名）
  和初中级已掌握词。它们在语料里出现次数最高，不滤掉会一直霸占清单前排，
  把真正该补的词挤到看不见的地方。
- 想继续扩词库，就打开它、按正文次数从高到低往下补。

### 手机上怎么用

页面是响应式的，窄屏自动切换成单手布局：

- **底部固定操作条**：复习 / 自测 / 未掌握 / 导出 / 重置，拇指直接够得到，
  不用再往页面顶部去点。开关状态靠**按钮底色变蓝**表示，不再靠改文字
  （原来「自测」会变成「自测已关」，多两个字在 320px 屏上就把整条挤爆）。
- **筛选区三行横滑**：搜索框一行、三个下拉一行、筛选片一行，后两行可左右滑，
  右侧有渐隐提示；搜索框字号 16px（避免 iOS 聚焦时页面被放大）。
- **每页 15 张**，滑到列表底部自动加载下一页。所以底部条里不再放「更多」
  按钮 —— 320px 屏内容区只有 304px，六个按钮每个只剩 42px 宽，不如去掉。
- **所有可点控件的有效点击区都不小于 44×44**（iOS HIG 的建议值）。
  ★ 收藏、例句行里的一个小喇叭、历史记录里的 × 这三处盒子故意留小
  （撑大会把卡片头部顶高、把行距顶开），改用 `::after` 向外扩点击区，
  看起来还是原样，手指点得准。
- **正文最小 12px**：桌面端那些 10.5~11.5px 的角标（等级、真题出现次数、
  年份题型、出处标签）在手机上一律提到 12px。
- **深色模式**：跟随系统。夜间刷词不刺眼，涨跌色等语义色保持一致。
- **离线可用**：构建会一并生成 `manifest.webmanifest` / `sw.js` / `icon.svg`，
  通过 https（GitHub Pages）打开一次之后，断网或地铁里也能直接背——
  导航请求走网络优先，所以重新构建后打开就是新版；断网时才回落到缓存。
  用 `file://` 双击打开时不会注册 service worker（没有 secure context），行为跟以前一样。

### 手机适配是怎么验的

不靠肉眼扫。`tests/audit_mobile.py` 会真起一个 headless Chrome，按
320 / 360 / 390 / 414px 四档宽度量：文档 `scrollWidth` 有没有超过视口、
哪些元素真的顶出屏幕（会把祖先里横向滚动容器内的元素排除掉，那种是设计要的横滑）、
用 `elementFromPoint` 在控件 44×44 有效区上打五个点验点击命中、
扫全页有没有小于 12px 的字、以及横屏 844×390 下的表现。

`tests/test_all.py` 的「H. 手机端」一节把结论固化成断言（三档宽度不溢出、
首屏控件点击区达标、无小字、底部条按钮尺寸与高亮态、下拉独立成行），
改坏了会当场报出来。

判定点击区时**取的是有效命中点，不是盒子尺寸**——这一点很关键：
★ 收藏的盒子实测 23×22，可它的 `::after` 把点击区扩到了 45×44，
只量盒子会永远误报不合格。同理，筛选片是胶囊形、喇叭是圆角矩形，
打四角必然落空，所以探测点是中心加四条边中点。

修掉的两个真问题：

- **320px 横向溢出 344px**。根因有两个，叠在一起：底部条上「自测」按钮
  在关掉时会变成「自测已关」，多两个字；`#mMore`（加载更多）虽然
  `display:none` 但它是 `inline-block`，`flex-wrap:nowrap` 下仍然占一个 flex 档位。
  六个按钮挤 304px，每个只剩 42px 宽还顶爆页面。
  改法：「自测」不再改文字，改成按钮底色变蓝表示开关；底部条去掉「更多」
  （手机上本来就有滚到底自动加载，列表里的按钮也还在）。
- **搜索框把整行撑到 332px**。`input{flex:1 1 100%}` 的 flex-basis 是 100%
  但 `min-width` 不为 0，它坚持自己 205px 的固有宽度不肯缩。
  改成 `flex:1 1 0; min-width:0` 才能被压下去。

另外把三个下拉从搜索行里拆出来单独成行：它们和搜索框挤一行时，
「按重要度（基础→进阶）」这个最长的选项把 `select` 撑到 180px，
换行后 sticky 顶栏变成三行高。拆开后下拉行自己横滑，顶栏高度稳定。

想把网页当 App 用：Safari 分享 → 添加到主屏幕；Android Chrome → 添加到主屏幕。

词库分册（共 2339 词，含 17 条固定搭配）：

| 文件 | 内容 |
|---|---|
| `01_A-C` ~ `07_Addendum` | 按字母序排列的四级核心词、补充词 |
| `08_BasicNouns.txt` | 最高频基础实词（people / time / city / work…） |
| `09_Function.txt` | **功能词与连接词**（although / because / while / whether…） |
| `10_BasicVerbs.txt` | 基础动词与常用变形（make / take / need / help / keep…） |
| `11_BasicTopics.txt` | 校园·医学·社会场景基础词（library / system / medicine…） |
| `12_Everyday.txt` | 生活场景基础词（body / exercise / payment / robot…） |
| `13_BasicGap.txt` | **真题高频但上面几册漏收的词**，正文出现 ≥3 次（open / save / eat / sell / task / idea…） |
| `14_MoreGap.txt` | 同一批漏收词，门槛放到正文出现 ≥2 次（accept / begin / danger / software / curriculum…） |
| `15_RestGap.txt` | 第三批，正文出现 ≥1 次（accommodation / atmosphere / computer / decision / bread / chance…） |

13、14、15 三册是这么来的：跑完 `run.py` 看 `output/未收录高频词.txt`，把正文里真出现过、
又不是功能词或题干套话的实词整批补进来。原分册 01-05 收的是"稍难的核心词"，
反而把 `eat / sell / pay / talk / save / open` 这类真正常出现的基础词漏了，
这三册就是补这个洞（合计 529 个词条）。
2026-11 又加了一册 `16_OutlineGap.txt`：拿大纲词表与未收录清单对账，
补上 basic / complete / finish / happen / bread / key 这类一直漏着的词，
命中重点词 1027 → 1634，真题例句 2455 → 3578。

15 册的入册标准比前两册严：门槛放到 1 次之后，混进来的专有名词与技术词
（alzheimer / confucius / chatgpt / algorithm / cardiovascular）和初中就已经会的词都排除了。
初中词没有进词库，而是进了 `data/stopwords.txt` 的第 5 类——
它们几乎每篇都出现，但人人都会，做卡片纯属浪费复习位。

还有一类是**"原形缺位"**：`got / eaten / shown / slept / thrown / drunk / born` 反复出现，
但词库里没有 `get / eat / show / sleep / throw / drink / bear` 这些原形，
于是 `IRREGULAR_PAIRS` 里那条映射永远命不中，整族词形全被记成未收录。
15 册补了原形就够，不用为每个变形单独建条。

补完之后还剩什么没收录，清单里会写清楚每个词"正文出现几次、总计几次"，
功能词和题干套话由 `data/stopwords.txt` 过滤掉，不再霸占前排。

### 词库里"故意没有"的词

`data/stopwords.txt` 里写着"做卡片没有学习价值"的词，词库**不应该**再给它们出卡——
这两处以前是打架的：62 个词同时在两个文件里，结果首页前几张卡是
`they(178 次) / are(124 次) / what / who / their` 这种没人会不认识的词。

现在的规则是**两条都满足才从词库里删**：

1. 在 `stopwords.txt` 里（已认定没有学习价值）
2. 搭配提示为空或 `—`（没有四级常考搭配可教）

按这条清理掉 34 个词（`are / is / was / were / of / to / they / them / we / us / you /
it / can / should / will / their / this / these / those / three / two / five …`）。
有搭配的一律留下——`have to / in order to / not at all / no longer / along with /
had better / on the other hand / thousands of` 这些对 370 分档是真有用的。

`are / is / was / were / does / did / has / had` 删掉不漏词：
`IRREGULAR_PAIRS` 会把它们折回 `be / do / have`（所以 `be` 现在 195 次排第一，卡面写"be able to 能够"）。
人称代词另行在 `stopwords.txt` 第 6 类备案，防止删掉之后又掉进「未收录词」清单。

为什么要专门分 09~12 这四册：四级 370 分档的典型卡点不是"生词不认识"，而是
**although / because / while 这类连接词一出现就断句**，以及 make / take / give / keep 这类
基础动词的**搭配**不熟。这些词在传统背单词 App 里常被归入"太简单、不收录"，
但在真题长句里恰恰是理解卡壳的地方，所以单独成册、全部标 A 级最高优先级。

**语料覆盖范围**：`2021-06` ~ `2026-06`，共 11 个场次、83 个题型块。其中：

| 批次 | 文件 | 性质 |
|---|---|---|
| 2021-06 ~ 2024-06 | 8 个文件 | 按真题题材、体裁与难度撰写的**仿真语料**，目的让工具开箱即用 |
| 2025-06 / 2025-12 / 2026-06 | 3 个文件 | **真题片段**：官方不公布原卷，内容取自考后答案整理与考生回忆版，逐句可溯源 |

2025、2026 年为什么只有片段、哪些字段查不到、各年轻重来源是哪几个链接，
全部写在 `data/2025-2026来源说明.md` 里，动手改之前建议先看那个文件。

### 译文怎么对上的

`data/translation/` 里的文件和 `data/corpus/` 一一对应，结构相同，区别是正文位置直接写中文：

```
#### 2024年6月 第1套
## 仔细阅读 | Passage One
@q 关于塑料污染，作者说了什么？     <- @q 开头是题干译文
塑料污染已经从公众讨论的边缘走到了中心。   <- 第 1 句的译文
多年来这个问题似乎很遥远……              <- 第 2 句的译文
```

按**句序**与英文段落对齐，一行一句。句数对不上时，`run.py` 会打印哪一块不一致，
缺的部分该句就不显示译文（不会串位）。你自己加真题时，译文可选——没有译文词照样能提取，
只是句子不带翻译。

## 四、换成你自己的真题（重要）

`data/corpus/` 里 **2021-06 ~ 2024-06 那 8 个文件**是**按四级真题体裁、题材与难度撰写的仿真语料**
（远程办公、塑料污染、AI 教学、选词填空、汉译英、写作范文等），
用于让工具开箱即用，不是官方原卷逐字文本。

想用真实真题，把文本丢进 `data/import/` 再跑一次 `python run.py` 即可，支持三种形式：

**1）纯文本（最简单）**——文件名带年份和题型就会被自动识别，例如
`2024-06-仔细阅读.txt`、`2023-12听力.txt`：

```
（直接粘贴真题原文，空行分段即可）
```

**2）结构化标记（推荐，能保留题目情境）**：

```
#### 2024年6月 第1套
## 仔细阅读 | Passage One
@topic 远程办公对城市通勤的影响
@question 46. What does the author say about remote work?
@choice A) It reduces commuting.
@choice B) It increases productivity.
@body
Remote work has reshaped the daily routine of millions of employees…
```

**3）PDF**——安装 `pip install pymupdf` 后，直接把真题 PDF 放进 `data/import/`。

## 五、自定义词库

`data/lexicon/*.txt` 每行一个词，管道分隔：

```
单词|词性|义项(分号分隔，带*者为常考义)|等级(A基础/B核心/C进阶)|搭配提示
```

示例：

```
access|n./v.|*使用权,通道;进入,获取|B|access to 有权使用
```

改完直接重跑 `python run.py`，不需要改任何代码。
遇到真题里有但词库没收的词，工具会写进 `output/未收录高频词.txt`，照格式补进去即可。

**四个字段一段都不能少。** 等级列必须是单独的 `A` / `B` / `C`，写成
`ability|n.|*能力,才能|ability to do 做…的能力`（漏了等级）会让搭配提示被顶到等级位上，
卡面就再也看不到那条搭配了。以前这种情况是静默的——等级列被截首字母，
`ability to do…` 恰好被读成 `A` 蒙混过关，`commuter` 则被读成 `C`。
现在加载器会严格校验并在 `run.py` 的体检输出里点名，坏数据按 B 兜底。

自查：`python .tools/audit_data.py` 会把格式错误、重复词条、词库与停用词打架的地方全列出来。

## 六、音标数据

音标单独放在 `data/phonetics/`，一行一个词，**不占用词库那五列**：

```
abandon|əˈbæn.dən
```

来源是开源音标库 [ipa-dict](https://github.com/open-dict-data/ipa-dict)（美音基于 CMUdict），
由 `.tools/fetch_phonetics.py` 抓取并**只保留 `data/lexicon/` 里出现过的词**：

```bash
python .tools/fetch_phonetics.py           # 美音 en_US（默认）
python .tools/fetch_phonetics.py en_GB     # 换英式音标
```

为什么只保留用得到的词：上游原始表 3 MB、13 万词条，全塞进仓库又大又没意义。
裁到词库规模后只有几十 KB，跟着仓库走，**构建过程完全不碰网络**。

几个要点：

- **缺音标不会报错**，那张卡片就不显示音标栏，只会在 `run.py` 的数据体检里提示还有哪些词缺。
- **符号已转成国内词书写法**。上游给的是美音音位变体，`ɹ ɫ ɝ ɡ` 这些符号音理上更准确，
  但和牛津／朗文／四级词汇书的写法对不上，学生拿去对照会以为看错了。加载时统一转换：

  | 上游 | 词书写法 | 说明 |
  |---|---|---|
  | `ɹ` | `r` | 美音 r 的变体符号 |
  | `ɫ` | `l` | 暗 l 变体 |
  | `ɡ` | `g` | U+0261 脚本 g，肉眼和 ASCII g 一样，但复制出去搜不到 |
  | `ɛ` | `e` | DRESS 元音，中文版牛津／朗文都写 /e/ |
  | `ɝ` | `ɜːr` | 重读卷舌元音，如 bird |
  | `ɚ` | `ər` | 非重读卷舌元音，如 teacher 词尾 |

  效果：`result /riˈzəlt/`、`world /ˈwɜːrld/`、`academic /ˌækəˈdemɪk/`。
  想要上游原样，改 `run.py` 里的 `Phonetics.load(DIR_PHON, normalize_symbols=False)`。
- 想改某个词的读音，写进 `zz_custom.txt`（见该文件头部说明），
  **不要直接改 `en_US.txt`**，那个文件会被抓取脚本整份重写。
- 音标用带 IPA 的字体渲染（Charis SIL / Lucida Sans Unicode 等），
  否则 `ˈ ˌ ə ʃ ŋ` 这些字符会掉进中文回退字体、变方框。
- 想换英音，跑 `fetch_phonetics.py en_GB` 后把 `en_US.txt` 删掉，
  两个文件同时存在时按文件名排序，后面的覆盖前面的。

## 七、给 370 分档的建议用法

1. **别一上来就盯着 1600 多个词**。打开页面点「今日 30」，每天就背这 30 个：
   到期复习的排前面，剩下的用没学过的词按等级补。一天 30 个，约 52 天走完一轮。
2. 想先聚焦：跑 `python run.py --levels AB --min-count 2`，拿到**真题里反复出现**的基础 + 核心词，约 1100 个。
   还嫌多就 `--levels B`（核心必背，368 个）或加 `--min-count 3`。
3. 按题型过一遍：先做**选词填空**和**仔细阅读**的词（这两块占分最高、原句最完整）。
4. 每词不要死记中文，看原句里它**和谁搭配**、**此处作什么词性**，卡片上都有标。
   句子前面标「仿真」的是撰写语料，用来熟悉语境；标「真题」的才是考场原句。
5. 过完一轮点"只看未掌握"筛出没记住的，第二天只复习这批。
6. 每套真题做完后，把该套的年份单独筛出来复习，趁热打铁。

## 八、构建与发布

```bash
python run.py --no-open        # 构建全部产物（含根目录入口页）
python tests/run_all.py        # 数据门禁 11 + 主回归 127 + 边界 72，共 210 条
python tests/audit_data.py     # 只跑数据门禁（纯 Python，秒级，不需要浏览器）
python tests/test_all.py       # 只跑主回归
python tests/test_edge.py      # 只跑边界回归
python tests/audit_mobile.py   # 手机端专项审计（四档宽度 / 点击区 / 字号）
python .tools/shots.py         # 重新出预览图
python .tools/reconcile_outline.py   # 词库 × 大纲对账，写 output/词库对账报告.md
```

**数据门禁**是提交前最划算的一步：不启浏览器，几秒内查完词库格式、音标覆盖率、
实词覆盖率、**大纲内未收录词数量**、有没有屈折形式独立成条、同族词与易混词的覆盖面。
它守的正是这次踩过的坑——`basic / complete / finish` 这类词漏了半年没人发现，
现在漏超过 30 个就直接失败。

- **入口页 `index.html` 由构建生成**。它的词数、例句数、场次、生成时间都取自当次构建结果，
  手改会被下一次 `run.py` 覆盖。之前这几个数字是写死的，词库一路涨上去之后
  首页一直写着 1016，线上因此长期落后一整版。
- 发布到 GitHub Pages 时把 `index.html` 与 `output/`（含 `manifest.webmanifest`、`sw.js`、
  `icon.svg`）一起推上去即可，页面之间用的是相对路径。
- `.github/workflows/ci.yml`：数据门禁 → 构建 → 真浏览器回归。浏览器那一步用
  `CET4_CHROME` 环境变量指定 Chrome 路径；`tests/cdp.py` 在没设时会按平台找一遍
  （Windows / Linux / macOS 常见路径），所以 CI 和本地都能跑。
- 仓库已纳入 git，建议改完跑一遍再提交：

```bash
git add -A && git commit -m "说明这次改了什么"
```

`.gitignore` 里排除了 `__pycache__` 与历史截图目录 `.shots/`。
测试与工具脚本都按**相对自身位置**算路径，换台机器、换个盘符不用改代码。

## 九、上传到 GitHub，拿到手机能打开的网址

目标：手机上打开一个链接就能背，还能「添加到主屏幕」当 App 用、断网也能用。

### 1. 生成一个 token（约 1 分钟）

打开 <https://github.com/settings/tokens> ，推荐用 **Fine-grained token**：

1. **Generate new token** → 名字随便写（如 `cet4-deploy`），有效期选 90 天
2. **Repository access** 选 `All repositories`（如果以后可能换仓库名，选这个最省事）
3. **Permissions** 里勾下面四项，缺一不可：
   | 权限 | 级别 | 为什么 |
   |---|---|---|
   | `Contents` | Read and write | 推代码 |
   | `Pages` | Read and write | 打开 / 校正发布源 |
   | `Workflows` | Read and write | **仓库里有 `.github/workflows/ci.yml`；没有这个权限，GitHub 会直接拒绝推送** |
   | `Administration` | Read and write | 仓库不存在时创建它 |
4. 生成后**只显示一次**，先复制下来

> 用经典 token（Classic）也行，勾 `repo` + `workflow` 两项即可。

### 2. 一条命令推上去

```bash
python .tools/deploy.py --token ghp_你复制的token
```

它会依次完成：

- 用 token 认出你是谁，仓库不存在就建一个 public 仓库
- 把远端原有历史拉下来，把当前内容作为**一个新提交接在后面**（不是 force push，之前的历史不会丢）
- 推送
- 打开 GitHub Pages，把发布源校正为默认分支的根目录
- 打印网址

只想先看看会发生什么（不推送）：

```bash
python .tools/deploy.py --token ghp_xxx --dry
```

### 3. 手机上打开

等 1~3 分钟，Pages 构建完成后打开：

```
https://<你的用户名>.github.io/cet4-word-miner/
```

- Android Chrome / iOS Safari：分享 → **添加到主屏幕**，之后像 App 一样全屏打开
- 打开过一次之后 Service Worker 会缓存整页，**地铁里断网也能背**
- 首次加载约 1MB（gzip 后），之后走缓存基本是秒开

### 4. 以后更新

改完代码，重新构建、跑一遍回归、提交，再跑一次同一条命令：

```bash
python run.py --no-open
python tests/run_all.py
git add -A && git commit -m "改了什么"
python .tools/deploy.py --token ghp_xxx
```

`sw.js` 的缓存名带着构建时间戳，浏览器会自动换到新版本，不用手动清缓存。

### 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `refusing to allow a Personal Access Token to create or update workflow` | token 没给 `workflow` 权限 | 按上面表格补上 `Workflows: Read and write` |
| `403 Resource not accessible by personal access token` | fine-grained token 没勾 `Administration` 或仓库范围没包含它 | 补权限，或把 Repository access 改成 All |
| 推送成功但页面还是旧版 | Pages 还在构建，或者 CDN 缓存 | 等 2 分钟；仍旧的强制刷新（Ctrl/Cmd+Shift+R） |
| 页面 404 | Pages 发布源不是根目录 | 重新跑一次 `deploy.py`，它会自动校正 |
| 手机上样式全乱 | 用了 `file://` 直传的版本 | 必须走 Pages 的 https 地址 |
